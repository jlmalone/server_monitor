# Security policy

## Supported versions

Security fixes target the latest released version and the current `master` branch.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use this repository's private
GitHub security-advisory reporting flow. Include the affected version, impact, minimal
reproduction, and whether the issue can bypass a configured service or infrastructure
control.

Remove host names, account names, addresses, credentials, filesystem paths, and unrelated
log content before attaching diagnostics. Never include Keychain values or private
configuration overlays.

Ordinary monitoring bugs and feature requests can use the public issue tracker.
